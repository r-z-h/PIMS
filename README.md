# PIMS — 工程企业项目成本管理系统

> 原名《基于大模型的工程企业预算-记账-结算一体化管理系统》。
> 经需求对齐后，大模型（AI 问答 / RAG / 科目推荐）、审批流、复式记账、权限体系、预算编制、进度款多级审批等一律不做。
> 本系统是一个**单机单用户**的工程项目成本台账工具：记项目、记钱、记五类成本、算两个利润。

## 一句话说明

老板在一台电脑上用浏览器打开，录入项目的收入和支出、人工 / 材料 / 机械 / 杂费 / 垫付五类成本，
系统实时算出每个项目的：

| 指标 | 公式 | 含义 |
|---|---|---|
| 预计利润 | 甲方预算 − 我方成本预算 | 签合同的时候就知道该赚多少 |
| 结算利润 | 甲方预算 − 实际成本 | 项目实际赚了多少 |

> 利润只看「合同额 − 成本」，**不看现金进出、不算现金结余**。

## 快速开始

**单机使用（推荐）**：双击根目录 [`start.bat`](start.bat)。

它做三件事：起后端 → 等后端真的就绪 → 打开浏览器 `http://127.0.0.1:8000/`。
逻辑在 [`scripts/start_pims.py`](scripts/start_pims.py)（不在批处理里写复杂逻辑：
批处理对换行符必须 CRLF、括号块、中文编码都极敏感，一旦出错会**静默退出、连报错都看不到**）。

> ⚠️ 踩过的坑：早先的 `start.bat` 是 LF 换行，双击一闪就没、什么提示都没有。
> 批处理必须用 **CRLF**，现在这份是纯 ASCII + CRLF（`scripts` 下改批处理时注意别被编辑器改成 LF）。

**开发模式**：

```bash
# 后端
cd backend
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000

# 前端（开发模式，/api 代理到 8000）
cd frontend
npm install
npm run dev        # http://localhost:5173
```

首次启动：默认密码 `123456` → 系统强制引导设置三个密保问题 → 开始录数据。
数据库文件在 `backend/data/pims.db`，删掉即可完全重置；每次启动自动备份到 `backend/data/backup/`。

## 第七批：项目列表按「名字 + 日期」筛选（2026-10-17）

| 之前 | 现在 |
|---|---|
| 日期只影响列表里的金额，**筛不了项目** | 日期能筛项目，两种口径下拉切换：**有业务数据** / **开工日期** |
| 首页与项目列表口径不一致 | 两处共用同一个设置，口径永远一致 |
| — | 可**和名字搜索叠加**；新建的项目不会因「还没数据」被筛没 |

## 第六批：项目「完工」锁（2026-10-17）

| 之前 | 现在 |
|---|---|
| 项目状态只是个标签，**完工了照样能改** | 完工即锁定，**所有写操作（成本/收付款/往来/冲销/结算/库存/项目档案/删项目）都要先输密码** |
| — | 被拦时**自动弹密码框 → 解锁 → 自动重试刚才那次操作**，不用重做一遍 |
| — | 解锁后一直有效，直到手动「重新锁定」；重启也保持 |
| — | 只读（报表/预览/导出）不受影响；「撤销完工」要密码 |

## 第五批（L1）：表格列名不再滚没了

| 之前 | 现在 |
|---|---|
| 往下滚时**工具条吸住了、列名却滚没了**，一串数字不知道哪列是哪列 | 列名贴在工具条下面**一直可见**，9 个页面 / 14 张表全站生效 |
| 根因：`<thead>` 的 `position: sticky` 被表格的横向滚动容器吃掉 | 改用 antd/rc-table 的 `sticky`（独立粘性容器，不依赖 thead），**横向滚动不受影响** |

## 第四批（T11）：结算页的「已发」不再自己记账

| 之前 | 现在 |
|---|---|
| 结算页的「已发」是它**自己另记**的一个数，跟应付单的冲销是两套账 → 在收/付款页付了钱，结算页不知道 | 「已付/还欠」一律由**应付单上的全部冲销记录**算出，**钱从哪个入口付的都算得进来** |
| 发放上限按这个错的数算 → **会多付**（沈八只欠 4000 却允许发 4500） | 上限＝累计应付 − 已付，**超过直接拦住** |
| 付款方式看不出构成 | 「付款方式构成」一列：微信 300 + 现金 200 |
| 一笔钱冲哪张单**不看付给谁** | 三级优先：**对方一致** → 同业务类型 → 全部未结（兜底） |

## 第三批（T9）：「结算」能结五类成本了

| 之前 | 现在 |
|---|---|
| 「结算」页**只能发工人工资** | 五个页签：**人工 / 材料 / 机械 / 杂费 / 垫付**，每类按自己的依据汇总（姓名 / 供应商 / 出租方 / 小类 / 垫付人） |
| 人工费走结算页，其余在往来页各自付款 | **所有应付单的付账统一走结算页**；往来页按钮改为「去结算」，点了跳到结算页对应页签并定位到那一行 |
| 结算单表只认人工 | 表加 `cost_type` + `partner`，**新增轻量迁移机制**（旧库自动加字段并回填，一条数据不丢） |

> 付账口子从两个收成一个，**不会再出现"结算页说已发、往来页说还欠着"**。

## 上一轮（成本↔应付单联动）修掉的缺陷

交付前由独立验证跑出并已修复的 6 个问题，其中 2 个是**真产品缺陷**：

| # | 问题 | 性质 |
|---|---|---|
| 1 | 记账/成本页「操作」列宽 210px，实际内容 226px → 1440 宽下「删除」按钮被卡片边缘**裁掉** | 真产品缺陷（已改列宽） |
| 2 | mock 后端 `DELETE /costs/{id}` 不返回 `payable.kept`，与真实后端契约不一致 → 「应付单已保留」提示在 mock 模式下永远不弹，且该 UI 分支**零覆盖** | 真契约缺口（已补 mock + 补测试） |
| 3 | 成本页文案自相矛盾：写着「本页不提供录入」，同屏却有「新增成本」按钮 | 文案（已重写） |
| 4 | JSX 里误写 Markdown `**`，被当字面量显示成 `但**对应的应付单会保留**` | 文案（已改 `<Text strong>`） |
| 5 | `smoke-packaged.mjs` / `real-backend-e2e.mjs` 断言依赖已被删除的旧文案「本页是只读汇总」→ 打包态冒烟稳定红 1 项 | 断言过期（已修） |
| 6 | `docs/04` 里 §0.1「只读」与 §0.2「两个入口都能录」自相矛盾 | 文档（已统一） |

**L1（表头吸顶）已修**（2026-10-17）：原来长列表滚动时表头会被吸顶工具条盖住
（antd 的 `.ant-table-content` 滚动容器让 `thead: sticky` 失效）。
改用 rc-table 自带的 `sticky`（独立粘性容器，不依赖 thead），横向滚动不受影响；
覆盖 9 个页面 / 14 张表，详见 [`docs/05-待改需求.md`](docs/05-待改需求.md) 的「已完成：L1」。

**精度与边界已验证的点**（第二轮自检补充，都是真实尺度数字，不是"整万"好数）：

- `2.5 吨 × 412.37 = 1,030.93`、`1.234 吨 × 100 = 123.40`、`0.5 工日 × 333.33 = 166.67`、`7.5 小时 × 88.88 = 666.60` —— 分位四舍五入正确
- 多笔相加**精确等于**各项之和，无浮点漂移；千万级 `98,765,432.10 − 87,654,321.05 = 11,111,111.05` 无精度损失
- 删除材料成本后**库存回冲为 0**（不留虚高），实际成本同步回退
- 合同额填 0 + 有成本 → 结算利润可为负并标红；金额 0 / 负数被拒（400）；领用超库存允许提交但 `enough=false`
- 浏览器侧：金额落库为 **number**（非千分位字符串），界面千分位两位小数，提交去千分位

Playwright 的溢出用例会扫 **9 个页面 × 4 种分辨率**（1280/1440/1680/1920），
截图产物在 `frontend/test-results/screenshots/`（已 gitignore，可随时重新生成）。

**跑测试的注意事项**

- `integration_smoke.py` 会临时改密码再改回（收尾已恢复），`smoke-packaged.mjs` 会设置密保和建项目。
  它们都会改变数据库状态，所以**每个套件用独立的干净库**跑，不要串在同一个库上按顺序跑，
  否则会出现「前置假设失效」的假故障（例如冒烟跑完后，登录不再落到密保页）。
- 建议给每个套件单独指定库：`$env:PIMS_DB_PATH = "$env:TEMP\pims_<套件名>.db"`。
- 真后端联调需要同时起后端 8000 与前端 dev server 5173，并让 `VITE_USE_MOCK=false`
  （可在 `frontend/.env.development.local` 临时覆盖，验完删除）。
