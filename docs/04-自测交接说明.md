## 0.2 成本 ↔ 应付单自动联动（2026-10-15 第三轮）

**录任何一笔成本（记账页或成本页），系统都会在同一时刻自动生成一张「应付单」**，进「往来」页的应付单列表。

| 环节 | 行为 |
|---|---|
| 录成本 | 自动生成应付单：金额＝**成本全额**、类型＝材料款/人工费/机械费/杂费/垫付、对方＝供应商/姓名/出租方/垫付人、日期＝成本发生日期 |
| 录完立刻 | 弹出「**登记已付**」窗口：**已付金额 / 支付方式 / 付款日期 / 备注，四个全是选填** |
| 填了已付金额 | 生成一笔付款流水（「收/付款」页可见），并**自动冲销**这张应付单，状态转「部分」或「已结清」 |
| 不填 / 直接关掉 | 当作已付 0，应付单**全额挂账**；以后在「往来」页点该单的「再付一笔」补齐 |
| 空着过几天再补 | 在「收/付款」页点行尾「登记已付」，或在「往来」页的应付单里「再付一笔」 |

**改和删的规则（重要）**

| 你做的事 | 系统怎么处理 |
|---|---|
| 改成本的**金额/对方/日期** | 对应的应付单**实时跟着改**（未冲销时） |
| 改一个**已经付过一部分**的成本金额 | **拒绝**，提示「请先到往来页撤销冲销」。这是故意的：否则已付金额和单据金额会打架 |
| 撤销冲销之后 | 就可以改了 |
| **删除**一笔成本 | 应付单**保留不删**，并弹窗提示你去「往来」页自行处理 |
| 只改备注、不改金额 | 即使已冲销也允许改 |

**两个入口都能录**：「记账」页像账本一笔记一笔，「成本」页按成本构成看汇总（右上角「新增成本」也能录）——两边是**同一套表单、同一份数据**，录哪边都一样。录的时候会提示已生成应付单，避免你在两边重录同一笔。

> 验证：后端 pytest **109 项全绿**（含 9 项专测这套联动）；
> 真后端端到端 **21 项全过**（自动生成 → 登记已付 → 冲销 → 超额拒绝 → 改额同步 → 已冲销拒绝 → 撤销后可改 → 删除保留）。

### T5 设置页：进页面时「修改密码」默认是收起的

- 点进「设置」，**修改密码**默认已收起，**字典维护直接铺满整页**

  现在**始终可见**（收起状态它们在字典维护下面），不会因为收起就找不到

### T6 结算页：发工资终于和「往来」对上账了

**这是这次最重要的一条。** 以前在结算页点「登记发放」，**只记了一笔发放，钱没有走账**——
结算单显示"已发"，但往来页那张应付单还是"未收付"，同一笔工资出现两种说法。

现在发放会同时做两件事：

1. **生成一笔付款流水**（业务类型＝人工费、对方＝工人姓名）——在「收/付款」页能看到
2. **自动冲销该工人的应付单**（同项目 → 人工费 → 日期最早优先）
   —— 往来页那张单会从「未收付」变成「部分」或「已结清」

发完会弹一个说明窗告诉你：冲了几张单、合计多少、**还剩多少没冲掉**
（如果发放额超过该工人未结的应付单，剩余部分会留在这笔流水上作为可冲余额，并提醒你核对是否多付了）。

> **一句话**：结算页和往来页现在是**同一本账**——这里发了多少，往来页就少欠多少。

### T7 人工费的付款入口统一到「结算」页

- 「往来」页里**人工费**的应付单，按钮从「付款」改成「**去结算**」，点了**跳到结算页**，不再在往来页直接付
- 原因：人工费原来有两个付款口子（往来页能付、结算页也能发），**两个口子会互相打架**；
  统一成一个，「结算页说已发、往来页说还欠着」这种矛盾就不会再出现
- **人工费的应付单仍然显示在往来页**（它是"我欠谁的全面清单"，少了人工费总数就对不上），只是不能在那里付
- 其他类型（材料款 / 机械费 / 杂费 / 垫付）**不受影响**，还是在往来页直接付款

### T8 跳过去会自动定位到那个人

- 从往来页点「去结算」跳过去时，结算页会自动切到该项目，并**只显示这位工人**，顶部有提示条
- 想看全部工人，点提示条上的「**显示全部工人**」即可

> 已知缺口（你说后续再补）：结算页现在只能按工天汇总发放，**没有工天的人（借支、预支）在结算页不会出现**，
> 而往来页又不让直接付人工费——所以这类钱暂时没有合适的入口。已记在 `docs/05-待改需求.md` 的「暂缓」里。

## 0.5 第三批整改：结算能结五类了（2026-10-16，T9）

**这一批把「结算」从"只发工人工资"改成了"所有要付的钱都在这儿结算发放"。**

### 结算页现在长什么样

顶部有**五个页签**，每类按自己的依据汇总：

| 页签 | 按什么汇总 | 说明 |
|---|---|---|
| **人工** | 工人姓名 | 还带总工天（跟以前一样） |
| **材料** | **供应商** | 按"跟谁买的"把钱归起来 |
| **机械** | **出租方** | 按"租的谁的设备"归起来 |
| **杂费** | **杂费小类** | 按伙食费/转运费/招待费…归起来 |
| **垫付** | **垫付人** | 按"谁先垫的钱"归起来 |

每类的流程**完全一样**（跟你原来发工资一样）：

```
选类别 → 生成结算预览（该付多少、已发多少、还发多少）
       → 保存结算单
       → 行尾「登记发放」 → 自动生成付款流水 + 冲销对应应付单
```

**没填对方的怎么算**：材料没填供应商、机械没填出租方的，会归到「**（未填对方）**」这一行，
同样能结算——不会因为它们被漏掉。

### 「往来」页现在只管两件事

1. **看**：我到底欠谁多少（那个"该付未付合计"仍然准）
2. **跳**：每张**应付单**行尾的按钮变成了「**去结算**」——点了直接跳到结算页，
   并且**自动切到对应页签、只显示这一条**（比如从材料款应付单跳过去，就落在「材料」页签、只显示那个供应商）

**详情抽屉里**的「再付一笔」也换成了「去结算」。

**应收单没变**：甲方给你钱（进度款/结算款）仍然在「收/付款」页收款，往来页里可以看。

### 一个使用上的变化，你要知道

以前在往来页点「付款」就能直接付；现在**所有付账都要走结算页**，也就是要先
「生成结算预览 → 保存结算单 → 登记发放」三步。

这是你要求的口径（付账统一到结算页），好处是**一个口子、不会两边打架**；
代价是**材料款这类"直接付掉"的场景多两步**。用着觉得绕的话告诉我，我可以给应付单加一个"直接付"的快捷口子。

### 数据

按你的要求**业务数据已清空**（成本/往来/流水/结算单/库存流水/变更日志全删），
字典和项目档案保留。改造前做的还原点已按你要求删除，**现在没有回退快照**了。

## 0.7 第五批整改：结算页的「已发」跟应付单对不上了（2026-10-16，T11）

### 你发现的问题

给沈八付了 500，往来页显示还剩 4000，但**结算页还是显示 4500 未付**。

### 原因

**结算页的「已发」是它自己另记的一个数，跟应付单上的实际冲销是两套账。**
钱有 4 个地方能进来（收/付款页、冲销弹窗、录成本后的「登记已付」、结算页发放），
**前三个都不会去更新结算页那个数**，所以你在收/付款页付了 500，结算页不知道。

**而且比"显示不对"更严重**：发放时的上限也是按这个错的数算的，
所以结算页当时会允许你再发 4500 —— **实际只欠 4000，存在多付的风险**。

### 现在改成什么样了

结算页变成**上下两张表**：

**① 欠款总览（新增，一对象一行，累计口径）**

| 姓名 | 应付金额（累计） | 已付（累计） | 还欠 | 状态 | 付款方式构成 | 本期该结 | 操作 |
|---|---|---|---|---|---|---|---|
| 沈八 | 4,500.00 | **500.00** | **4,000.00** | 部分 | 微信 300 + 现金 200 | 4,500.00 | 登记发放 |

- **已付**＝这个人名下应付单上**所有冲销记录的总和**——**不管钱从哪个入口付的都算得进来**
- **付款方式构成**：现金 / 微信 / 银行卡 / 转账 都体现，合成一列显示
- **还欠**＝应付 − 已付，这就是**发放的上限**（沈八最多只能再发 4000）
- 顶部的时间段**只决定显示哪些人**，不改上面的累计金额（"本期该结"那列才跟时间段有关）
- **已经付清的人默认不显示**，勾选右上角「含已结清」就能看到

**② 本期结算单（保留）**：只记"这一期该结多少"，不再显示已发/未发。

### 三个行为变化你要知道

1. **发放按钮移到了「欠款总览」表**（那里才有正确的"还欠"上限），下面的结算单列表只做查看/删除
2. **发多了会被拦住**：比如沈八还欠 4000，你填 4500，系统直接拒绝并告诉你原因
3. **删掉某期结算单不影响已经付出去的钱**（钱在付款流水里，结算单只是快照）

### 顺带查出来并修掉的一个真 bug

验证时撞出来的：**原来的自动冲销不看这笔钱是付给谁的**——只按"同项目 + 同类型 + 日期最早"。

结果就是：你给**李四**发 1500 工资，系统会先去冲**张三**更早的那笔欠款，李四那笔还挂着。
从"谁欠谁"的角度，**这钱记错人了**。

现在是三级优先：**① 对方一致 → ② 同业务类型 → ③ 全部未结（兜底）**。
如果你觉得"就该按日期最早冲、不管付给谁"，说一声我改回去。

### 你的存量数据

启动时会把结算单里那个旧的"已发"数字**清零**（它已经不作数了，留着会误导），
现在看到的"已付/还欠"全部按应付单的冲销记录现算，**跟你库里真实付出去的钱一致**。

## 0.9 第七批整改：「完工」锁项目（2026-10-17）

### 现在完工是什么效果

项目点「完工」之后，**这个项目的所有改动都要先输密码**：

- 录成本（五类）、改成本、删成本
- 新增/修改/删除 收付款流水
- 新增/修改/删除 往来单、冲销、撤销冲销
- 结算：保存结算单、登记发放、删结算单
- 库存：入库、领用、改流水、删流水
- 改项目档案本身、删项目

**看数据完全不受影响**：报表、预览、导出、结算总览照样能看。

### 你会在哪看到它

| 位置 | 表现 |
|---|---|
| 项目列表「状态」列 | 「在建」→「**完工·已锁**」 |
| 项目列表/详情 工具栏 | 在建时是「完工」；完工后变成「撤销完工」「解锁」/「重新锁定」 |
| 项目详情顶部 | 一条提示：已锁定（说明去改会弹密码框）或已解锁（带「重新锁定」按钮） |

### 关键体验：不用重做一遍

比如你在「记账」里录一笔成本，点确定后被拦——**系统会直接弹密码框**，
输对密码后**这笔成本自动保存好**，不用回去重新填。

输错密码只提示「密码不正确」，弹窗留着让你再试。

### 口径（你确认过的）

- 解锁用**登录密码**（不用另设）
- 解锁后**一直有效**，直到你点「重新锁定」（不是倒计时，重启应用也保持）
- 「完工」和「重新锁定」不要密码（往安全方向走）；「撤销完工」「解锁」要密码
- 撤销完工后项目变回「在建」，所有改动又不需要密码了

> 技术上：校验在**后端**统一做（前端藏按钮只是提示，接口直接调也会被拦），
> 所以不存在"从别的页面绕过"的可能。

## 1. 怎么开始用

1. 双击根目录的 `start.bat`
2. 浏览器自动打开 `http://127.0.0.1:8000`
3. 初始密码 `123456`；首次登录会强制你设 3 个密保问题
4. 数据存在 `backend/data/pims.db` 这一个文件里，**拷走它就等于备份**（启动时也会自动备份，留 7 份）

## 2. 建议的自测顺序

1. 建一个你自己的真实项目：填**甲方预算（合同额）**和**我方成本预算**
2. 首页立刻应显示 **预计利润 = 甲方预算 − 我方成本预算**（例：400 万 − 350 万 = 50 万）
3. 录几笔真实成本：人工（人×天×日工价）、材料（采购）、机械（台班/小时）、杂费、垫付
4. 每录一笔回首页看 **实际成本** 和 **结算利润 = 甲方预算 − 实际成本** 有没有跟着动
5. 用你自己的口算对一遍 —— **这是最有价值的一步**
6. 再试：应收单 + 收款冲销、领用出库、人工结算，看未收未付/库存余量/结算金额对不对
7. 最后点一次「导出 Excel」，看 11 个工作表的数据跟页面是否一致

## 3. 这些是**设计如此**，不是 bug

| 现象 | 说明 |
|---|---|
| 首页没有「现金结余」 | 按需求只做经营口径：`合同额 − 成本`，**不看钱进出** |
| 录了工天，实际成本立刻增加 | 人工按工天**实时入成本**（这是确认过的口径） |
| 人工结算后成本不变 | 结算只汇总应付 + 记发放，**不重复计成本** |
| 材料领用后实际成本不变 | 采购时已计成本；领用**只减库存** |
| 项目完工剩的料照旧算成本 | 不做退还/退货/调拨，剩余料留在项目上 |
| 应收/应付不影响利润 | 只反映该收该付，跟利润无关 |
| 项目档案表在 1440 宽度下容器内可横滚 | 12 列信息都有用，横滚是刻意的（页面本身不横滚） |
| 录错的账能改能删 | 会留一条修改记录（成本行有「修改记录」入口） |
| 领用超过库存能提交 | 会标红提示，但允许（工地常见先领后补录） |

## 4. 已知限制（还没做，别当 bug 报）

- 备份**已验证可恢复**（拷出备份文件能正常打开、数据完整），但"覆盖回正式库"这一步建议先复制当前库留底
- `/api/system/reset`（清空业务数据保留密码）后端有，**前端没放入口**
- 图表只有项目详情一张成本构成饼图，没做趋势图/仪表盘
- 未做：手机端、多用户协同、权限角色、审批流、AI 问答（都是确认过不做的）
