# 00 — 需求冻结

> 本文是需求对齐的最终结论，是后续所有设计、编码、测试的唯一依据。
> 来源：《拟开发软件信息表》（客户提供的需求文档）+ 2026-10-14 需求对齐问答。
> **原文档的口径已作废**，以本文为准。

---

## 1. 系统定位

| 项目 | 结论 |
|---|---|
| 目标用户 | **只有老板（老板一人使用）**，不做协同 |
| 使用范围 | **单公司、多项目**；项目之间数据干净隔离 |
| 运行形态 | **Web 应用**，本地跑（`uvicorn` + 前端静态页），后续可转 WebView2 桌面 App |
| 终端 | **电脑端**（不做手机适配，不做拍照上传） |
| 数据库 | **SQLite 单文件**（免安装服务，拷走即搬迁） |
| 登录 | 一个简单密码，打开输一次；**不做角色、权限、菜单权限、数据隔离** |
| 外部对接 | **全部不做**：无税务申报、无银行直连、无发票查验、无短信/推送 |
| AI | **暂时不介入**：不做大模型问答、不做 RAG 知识库、不做科目推荐、不做自然语言查账 |

## 2. 与原文档的差异（原文档九大模块的处理）

| 原文档功能 | 处理 | 原因 |
|---|---|---|
| 1. 用户与权限管理（7 角色、JWT、RBAC、菜单/按钮权限、操作日志） | ❌ 只保留「一个密码 + 三个密保问题」 | 单机单用户，不需要权限体系 |
| 1. 基础数据管理（会计科目、成本科目、税率、结算方式） | ⚠️ 只保留：项目档案、杂费小类、材料/单位字典 | 无复式记账，科目体系无意义 |
| 2. 项目与合同管理（五类合同、条款、付款条件、质保金、税率） | ❌ 只做项目档案 | 不做合同台账，合同信息就是项目上的「甲方预算」 |
| 2. 项目进度维护 | ⚠️ 简化为「在建 / 完工」状态 | 不做甘特图、节点 |
| 3. 预算编制与对比（多版本、审批、调整、偏差预警） | ⚠️ 简化为项目上两个数：**甲方预算**、**我方成本预算** | 不做预算编制工作流 |
| 4. 记账与凭证管理（复式凭证、借贷平衡、审核/反审核、期末结账、银行对账） | ❌ 全部不做 | 只做**资金流水**（收/付流水账），不做会计分录 |
| 5. 工资管理（考勤、多种工资标准、社保、工资表） | ⚠️ 简化为**人工成本**：姓名 + 工日数 + 日工价 | 不做考勤机对接、不做个税社保 |
| 6. 成本管理（多维核算、费用分摊、异常检测） | ⚠️ 保留**五类成本**：人工 / 材料 / 机械 / 杂费 / 垫付 | 不做多维核算与分摊 |
| 7. 进度款与结算管理（多级审批、台账、四类结算、差异分析） | ⚠️ 保留为**应收/应付单据 + 手工冲销**，不做审批 | 基本流程足够 |
| 8. AI 问答与科目推荐 | ❌ 暂时不介入 | 需求方明确 |
| 9. 报表与可视化看板 | ⚠️ 保留**项目盈亏总表** + 明细列表 + Excel 导出 | 不做驾驶舱大屏 |
| 非功能：并发、Docker Compose + Nginx、MinIO、Redis、MySQL | ❌ 全部不做 | 单机单用户，SQLite 足够 |

> 原文档标题《基于大模型的工程企业预算-记账-结算一体化管理系统》中的「基于大模型」已不成立，
> 系统名与作业文档口径由需求方另行决定（**本文不负责改那份文档**）。

## 3. 功能需求（FR）

### FR-1 登录与密码

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-1.1 | 单密码登录 | 初始密码 `123456`；登录后保持会话，打开页面不用反复输 |
| FR-1.2 | 首次强制设置密保 | 首次登录后必须设置 **3 个密保问题 + 答案**，才能进入系统 |
| FR-1.3 | 修改密码 | 必须 **3 个密保问题全部答对** 才允许修改，**无其他后门** |
| FR-1.4 | 放弃找回 | 密保也忘了：只能删除数据文件重新初始化（本地单机，无管理员可找） |

### FR-2 项目管理

| 编号 | 需求 |
|---|---|
| FR-2.1 | 新建 / 编辑 / 删除项目 |
| FR-2.2 | 项目字段：项目名称、甲方（业主）、地点、负责人、开工日期、状态（在建/完工） |
| FR-2.3 | 项目字段：**甲方预算（合同额）**、**我方成本预算** |
| FR-2.4 | 项目字段：项目成员名单（纯名单，不做权限） |
| FR-2.5 | 项目列表显示两个利润与已发生成本 |

### FR-3 资金流水（记账）

| 编号 | 需求 |
|---|---|
| FR-3.1 | 按项目记录收 / 付流水 |
| FR-3.2 | 收入类型：进度款、结算款、预支、其他 |
| FR-3.3 | 支出类型：材料款、人工费、机械费、杂费、垫付、其他 |
| FR-3.4 | 流水字段：日期、项目、收/付、金额、**对方**（付给谁 / 收自谁）、**支付方式**（现金/微信/银行卡/转账）、备注 |
| FR-3.5 | 资金流水 **只反映钱的进出**，不参与利润计算 |

### FR-4 应收应付与冲销

| 编号 | 需求 |
|---|---|
| FR-4.1 | 录「应收单」：类型＝进度款 / 结算款；字段：项目、日期、金额、对方、备注 |
| FR-4.2 | 录「应付单」：类型＝材料款 / 人工费 / 机械费 / 杂费 / 垫付 / 其他 |
| FR-4.3 | 收款 / 付款时，从**待冲销单据列表**里**手工勾选**，生成冲销记录 |
| FR-4.4 | 单据区分「未收/未付」「部分」「已结清」状态，可查未收未付余额 |
| FR-4.5 | **应收应付不参与利润计算**（利润只看合同额 − 成本） |

### FR-5 五类成本

| 编号 | 类别 | 字段 | 入成本时点 |
|---|---|---|---|
| FR-5.1 | 人工 | 项目、姓名（手输，无档案）、日期、工日数、日工价、金额＝工日×日工价、备注 | **录入当天即入成本** |
| FR-5.2 | 材料 | 项目、材料名称、数量、单位、单价、金额、供应商、日期、备注 | **采购即成本** |
| FR-5.3 | 机械 | 项目、设备名称、计量方式（台班/小时）、数量、单价、金额、出租方、日期、备注 | 录入即成本 |
| FR-5.4 | 杂费 | 项目、**小类（可自定义）**、金额、日期、备注 | 录入即成本 |
| FR-5.5 | 垫付 | 项目、金额、日期、垫付人、事由、备注 | 录入即成本 |
| FR-5.6 | 修改 / 删除 | 五类成本均可改可删，**但必须留一条修改记录** | — |

> **人工入账口径（重要）**：按工天**实时**入成本；
> 项目结束后的「人工结算」只是**按人汇总应付金额 + 记录发放**，**不再重复扣一次成本**。

### FR-6 库存（按项目隔离）

| 编号 | 需求 |
|---|---|
| FR-6.1 | 材料入库：项目、材料名称、数量、单位、单价、日期、供应商 |
| FR-6.2 | 材料领用：项目、材料名称、数量、单位、日期、备注 |
| FR-6.3 | 余量 ＝ 入库 − 领用，**按项目 + 材料名称 + 单位**分别计算，项目之间干净隔离 |
| FR-6.4 | **领用只减库存，不再产生成本**（成本已在采购时计入） |
| FR-6.5 | **不做退还 / 退货 / 调拨** |
| FR-6.6 | 项目完工后没用完的材料**留在项目上，照样算成本**（不冲回） |

### FR-7 人工结算

| 编号 | 需求 |
|---|---|
| FR-7.1 | 对某个项目发起结算：按**个人**汇总「总工天数、应付金额」 |
| FR-7.2 | 每条结算记录可记发放金额、发放日期、发放方式、状态（未发/部分/已发） |
| FR-7.3 | 结算**不新增成本**，只产生应付与发放记录 |

### FR-8 利润与看板

| 编号 | 需求 |
|---|---|
| FR-8.1 | **预计利润 ＝ 甲方预算 − 我方成本预算** |
| FR-8.2 | **结算利润 ＝ 甲方预算 − 实际成本**（五类成本合计） |
| FR-8.3 | 首页＝**项目盈亏总表**，一屏看完所有项目 |
| FR-8.4 | 项目详情：五类成本构成、已收已付、未收未付、库存余量、人工结算情况 |
| FR-8.5 | 按 **成本发生日期** 任意时间段筛选（发生日期 = 录入时填的那个日期） |
| FR-8.6 | **不做**「现金结余」口径，不看资金进出对利润的影响 |

### FR-9 查询、导出、留痕

| 编号 | 需求 |
|---|---|
| FR-9.1 | 明细列表：资金流水、人工、材料、机械、杂费、垫付、库存、应收、应付 |
| FR-9.2 | **导出为一个 Excel、多个工作表**（项目盈亏 / 资金流水 / 人工 / 材料 / 机械 / 杂费 / 垫付 / 应收 / 应付 / 库存） |
| FR-9.3 | 所有增删改写入变更日志表（表名、记录 ID、动作、变更前后快照、时间） |

## 4. 非功能需求（NFR）

| 编号 | 需求 |
|---|---|
| NFR-1 | 界面友好、操作路径短：录一笔成本不超过 3 次点击 + 填写 |
| NFR-2 | 单机运行，无需安装数据库服务；启动后浏览器可访问 |
| NFR-3 | 数据仅存本地 SQLite 文件，不上传云端 |
| NFR-4 | 金额精确到分（`NUMERIC(14,2)`，后端用 `Decimal`，不用 float） |
| NFR-5 | 页面列表默认分页 20 条，支持按项目 / 时间段筛选 |
| NFR-6 | 导出 Excel 单文件多 Sheet，列名中文，金额千分位 |
| NFR-7 | 代码结构清晰，前后端分离，便于后续扩展（如接大模型） |
| NFR-8 | 数据库变更用简单迁移脚本或初始化脚本，不做复杂迁移框架 |

- 角色 / 权限 / RBAC / 菜单权限 / 数据隔离 / 多用户协同
- 审批流（预算审批、凭证审核、进度款多级审批）
- 复式记账、会计科目、记账凭证、借贷平衡、期末结账、反结账
- 预算编制工作流、预算版本、预算调整、超预算预警
- 进度款审批、竣工结算工作流、四类结算与差异分析
- AI：大模型问答、RAG 知识库、科目推荐、自然语言查账
- 税务申报接口、银行直连、发票查验、电子签章
- 材料退还 / 退货 / 项目间调拨
- 多公司 / 分公司 / 集团组织架构
- 手机端、拍照上传、消息推送
- MySQL / Redis / MinIO / Docker Compose / Nginx（原文档技术栈已替换）

## 6. 关键业务规则（口径，写代码不得擅自改）

| 规则 | 定义 |
|---|---|
| R1 | 实际成本 ＝ 人工 + 材料 + 机械 + 杂费 + 垫付 五类之和（`deleted=0`） |
| R2 | 预计利润 ＝ 项目.甲方预算 − 项目.我方成本预算 |
| R3 | 结算利润 ＝ 项目.甲方预算 − R1 |
| R4 | 资金流水、应收、应付 **不影响** R1/R2/R3 |
| R5 | 材料：采购即成本；领用只减库存 |
| R6 | 人工：按工天实时入成本；结算只做汇总与发放，不重复入成本 |
| R7 | 库存余量按「项目 + 材料名称 + 单位」计算；不做退还 |
| R8 | 时间段筛选按成本、流水的**发生日期**（业务日期），不是创建时间 |
| R9 | 冲销必须手工指定单据，不做自动冲最早 |
| R10 | 全部业务表软删除（`deleted`），删除与修改都写变更日志 |
