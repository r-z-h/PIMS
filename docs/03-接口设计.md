## 1. 通用约定

### 1.1 路径与格式

| 项 | 约定 |
|---|---|
| 前缀 | 全部 `/api` |
| 数据格式 | 请求/响应均 `application/json`，字段 `snake_case` |
| 日期 | `YYYY-MM-DD` 字符串 |
| 金额 | 字符串或数字，后端统一按 `Decimal` 两位小数处理；响应中金额返回**数字**（保留两位） |
| 时间戳 | ISO8601 字符串 |

### 1.2 统一响应体

```json
{ "code": 0, "message": "ok", "data": { } }
```

| code | 含义 |
|---|---|
| 0 | 成功 |
| 400 | 参数校验失败（`message` 为中文提示，前端直接弹出） |
| 401 | 未登录 / 会话过期（前端跳登录页） |
| 403 | 密保答案不正确 / 无权限操作 |
| 404 | 对象不存在 |
| 409 | 业务冲突（如重复结算、项目下有数据不允许删除） |
| 500 | 服务端异常（写入日志，`message` 给通用提示） |

### 1.3 认证

- 登录成功后服务端在 `sys_setting` 写 `session_token`，并通过 **HttpOnly Cookie**（`pims_session`）下发，默认有效期 7 天。
- 除 `POST /api/auth/login`、`GET /api/auth/status`、`POST /api/auth/password/reset` 外，其余接口都需要有效会话。
- 单用户系统：任何一次登录都会覆盖旧的 `session_token`。

### 1.4 通用查询参数

列表接口统一支持：

| 参数 | 类型 | 说明 |
|---|---|---|
| `page` | int | 默认 1 |
| `page_size` | int | 默认 20，最大 200 |
| `project_id` | int | 可选，项目筛选 |
| `start_date` / `end_date` | date | 可选，按**业务发生日期**筛选 |
| `keyword` | string | 可选，模糊搜索（对方、姓名、材料名、备注） |
| `include_deleted` | bool | 默认 false，是否包含软删除记录 |

列表响应体：

```json
{
  "code": 0, "message": "ok",
  "data": { "total": 128, "page": 1, "page_size": 20, "items": [ ] }
}
```

## 2. 认证与系统 `/api/auth`、`/api/system`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/auth/status` | 查询系统状态：是否需要初始化密保、是否已登录、是否仍是初始密码 |
| POST | `/api/auth/login` | 密码登录 |
| POST | `/api/auth/logout` | 退出登录 |
| GET | `/api/auth/security-questions` | 取 3 个密保**问题**（不含答案），用于忘记密码页 |
| POST | `/api/auth/security/verify` | 校验 3 个密保答案是否全对（不通过不透露哪题错） |
| POST | `/api/auth/security/setup` | 首次设置 3 组密保问题与答案（登录后调用） |
| POST | `/api/auth/password/change` | 修改密码（**需已登录 + 3 个密保答案全对**，不校验旧密码，见下方口径说明） |
| POST | `/api/auth/password/reset` | 忘记密码（未登录场景）：3 个密保全对 → 重置为新密码 |
| POST | `/api/system/backup` | 备份数据库文件，返回备份文件路径 |
| POST | `/api/system/reset` | 危险操作：清空业务数据（保留密码与密保），需二次确认参数 `{ "confirm": "RESET" }` |

> **改密口径（以 `00-需求冻结.md` FR-1.3 为准）**：改密码**必须 3 个密保问题全对**，系统不设其他后门。
> 因此 `password/change` 与 `password/reset` 的必填字段相同：**三个密保答案 + 新密码**；
> `password/change` 额外要求已登录（`reset` 用于忘记密码、未登录场景）。
> 两者都不要求、也不校验旧密码（若前端传了 `old_password`，后端接受但忽略，兼容旧调用）。
> **改密成功后不使当前会话失效**（无需重新登录）。

**请求示例**

```jsonc
// POST /api/auth/login
{ "password": "123456" }
// → { "code": 0, "data": { "logged_in": true, "security_ready": false, "is_initial_password": true } }
//    security_ready=false 时前端强制跳「设置密保」页

// POST /api/auth/security/setup
{ "questions": [
    { "question": "我第一辆车的车牌号？", "answer": "鄂A12345" },
    { "question": "我母亲的姓名？",       "answer": "李秀兰" },
    { "question": "我小学的名字？",       "answer": "实验小学" }
] }

// POST /api/auth/security/verify   （返回临时票据，供 reset 使用）
{ "answers": ["鄂A12345", "李秀兰", "实验小学"] }
// → { "code": 0, "data": { "ticket": "rst_9f2c...", "expires_in": 300 } }
//   任一题错误 → { "code": 403, "message": "密保答案不正确" }

// POST /api/auth/password/reset      （未登录：忘记密码场景）
{ "ticket": "rst_9f2c...", "new_password": "abc12345" }

// POST /api/auth/password/change     （已登录：设置页改密码，口径见上）
//   前端实现为一次调用：直接传三个答案 + 新密码
{ "answers": ["鄂A12345", "李秀兰", "实验小学"], "new_password": "abc12345" }
//   任一答案错误 → { "code": 403, "message": "密保答案不正确" }（不透露哪题错）
//   后端尽可能兼容：同时接受可选的 "ticket" 字段（等价于已通过 verify）
```

> **时间段筛选口径（统一）**：`start_date` / `end_date` 一律按**业务发生日期 `biz_date`** 过滤，
> 作用范围包括：五类成本、资金流水、应收应付单。
> 首页的 `received` / `paid` / `unreceived` / `unpaid` 同步受该时间段影响；
> 而 `client_budget` / `cost_budget` / `expect_profit` 是项目档案属性，**不随时间段变化**。

## 6. 应收应付与冲销 `/api/arap`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/arap` | 列表（`type`=receivable/payable、项目、时间段、`status`、关键字） |
| POST | `/api/arap` | 新增应收单 / 应付单 |
| GET | `/api/arap/{id}` | 详情（含冲销历史） |
| PUT | `/api/arap/{id}` | 修改（金额不得小于已冲销额，否则 400） |
| DELETE | `/api/arap/{id}` | 软删除（已有冲销时 409） |
| GET | `/api/arap/pending` | 待冲销单据（`project_id` + `type` 必填，`status <> closed`） |
| POST | `/api/arap/offset` | **手工冲销**：一次可冲多张单据 |
| DELETE | `/api/arap/offset/{id}` | 撤销某条冲销（回滚 `settled_amount` 与状态） |
| GET | `/api/arap/auto-offset/plan` | **自动冲销计划（只算不写）**：按「同项目、同业务类型、日期最早优先」算建议，供「预冲窗口」展示 |
| POST | `/api/arap/auto-offset/apply` | 按自动规则**直接执行**冲销；无可冲单据时 `applied=false` 并给出提示（不报错） |
| GET | `/api/arap/summary` | 该收未收 / 该付未付合计 |

```jsonc
// POST /api/arap  （应收单）
{ "project_id": 1, "type": "receivable", "biz_type": "progress",
  "amount": 500000.00, "biz_date": "2026-06-01",
  "partner": "某某置业有限公司", "remark": "第三次进度款" }

// POST /api/arap/offset  （收 30 万，手工勾选冲销）
{
  "funds_flow_id": 18,             // 对应的收款流水
  "offsets": [
    { "ar_ap_id": 5, "amount": 200000.00 },
    { "ar_ap_id": 6, "amount": 100000.00 }
  ],
  "offset_date": "2026-06-20",
  "remark": ""
}
// 后端规则：单张冲销额 ≤ 单据未结额；冲销合计 ≤ 流水金额；随后重算 status 与 settled_amount
```

### 6.1 自动冲销（付款/收款保存后的「预冲窗口」，2026-10-16 需求 T4）

```jsonc
// GET /api/arap/auto-offset/plan?funds_flow_id=18   —— 只算不写
// → { "funds_flow_id": 18, "direction": "out", "arap_type": "payable",
//     "flow_amount": 60000.00, "already_offset": 0.00, "available": 60000.00,
//     "plan": [ { "ar_ap_id": 2, "biz_date": "2026-06-05", "biz_type": "material",
//                 "biz_type_label": "材料款", "partner": "某某建材",
//                 "amount": 700000.00, "unsettled": 700000.00,
//                 "amount_to_offset": 60000.00 } ],
//     "plan_total": 60000.00, "remaining": 0.00, "has_candidate": true,
//     "message": "按「同项目、同业务类型、日期最早优先」自动冲销 1 张单，合计 60000.00。" }

// POST /api/arap/auto-offset/apply?funds_flow_id=18  —— 直接按规则冲
// 无可冲单据时：{ "applied": false, "offset_ids": [], "message": "本次未找到可冲销的应付单…" }
// 正常时：     { "applied": true, "offset_ids": [7], ...create_offset 的返回 }
```

**规则（必须可预期）**

| 规则 | 说明 |
|---|---|
| 优先级 | **同项目** → **同业务类型** → **日期最早**（同日按 id，顺序稳定） |
| 业务类型兜底 | 该类型没有未结单据时，放宽到同类型的全部未结单据（避免"明明有欠款却冲不了"） |
| 金额不够冲一张 | 该单形成「部分」，余额继续冲下一张 |
| 冲完仍有余款 | **留在该笔流水上作为可冲余额**（`unoffset_amount`），不报错、不丢弃 |
| 找不到可冲单据 | 正常保存流水，`applied=false` + 提示「本次未找到可冲销的…」 |
| 只冲同方向 | 收款只冲应收、付款只冲应付 |
| 用户确认才落库 | `plan` 接口不写库；界面用它的结果预填「预冲窗口」，用户可自行增删改后再走 `/api/arap/offset` |

**前端交互**（`frontend/src/pages/Payments.tsx`）：
保存付款/收款 → 调 `plan` → 有可冲单据则弹「预冲窗口」（预填、可改）→ 用户确认 → 弹结果窗
（冲了哪几张、每张多少、还剩多少）+「撤销并重选」（撤销后弹回手工勾选窗口）；
没有可冲单据则只提示一句，不弹窗、不报错。

## 7. 五类成本 `/api/costs`

统一列表与查询：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/costs` | 五类混合列表（`type` 可选，多选用逗号：`type=labor,material`） |
| GET | `/api/costs/summary` | 汇总：按 `type` 分组金额、按 `category` 分组（杂费小类）、按项目、按时间段 |
| PUT | `/api/costs/{id}` | 修改成本（自动按 `type` 同步明细表）；**同步更新自动生成的应付单**，该应付单已被冲销时返回 400 |
| DELETE | `/api/costs/{id}` | 软删除成本（材料类同时回冲库存入库流水）；**返回 `payable` 字段说明应付单已保留** |
| GET | `/api/costs/{id}/logs` | 该条成本的修改记录（时间线） |
| GET | `/api/costs/{id}/brief` | **成本轻量摘要**（类别/对象/金额/日期），供「关联成本」列显示与悬停；不加载四张明细表 |
| GET | `/api/costs/{id}/payable` | **该成本自动生成的应付单**（含已付合计/未结/冲销明细），供「登记已付」弹窗预填 |
| POST | `/api/costs/{id}/pay` | **登记该成本的已付金额**：生成付款流水 + 自动冲销应付单（四字段全选填） |

分类录入（每个类型一个原子接口，**一次事务写主表 + 明细表 +（材料还要写库存）+ 自动生成应付单**）：

> **2026-10-15 起**：录任何一笔成本都会在**同一事务**里自动生成一张应付单，
> 金额＝成本全额，`cost_id` 关联该成本，业务类型按类别映射：
> 人工→`labor`、材料→`material`、机械→`machine`、杂费→`misc`、垫付→`advance_pay`；
> 对方取该成本的 `partner`（供应商/出租方/姓名/垫付人）。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/costs/labor` | 录工天：**实时计入成本** |
| POST | `/api/costs/misc` | 录杂费 |
| POST | `/api/costs/advance` | 录垫付 |
| POST | `/api/costs/machine` | 录机械费 |
| POST | `/api/costs/material` | 录材料采购：**同时写库存入库** |

### 7.1 登记已付（录完成本弹窗用）

```jsonc
// GET /api/costs/33/payable   —— 弹窗预填
// → { "has_payable": true,
//     "arap": { "id": 12, "amount": 40000.00, "settled_amount": 0, "unsettled": 40000.00, "status": "open" },
//     "offsets": [],
//     "paid_total": 0.00,
//     "unsettled": 40000.00 }

// POST /api/costs/33/pay     —— 四个字段**全部选填**
{
  "paid_amount": 40000.00,     // 不传或传 0 → 什么都不做，应付单全额挂账
  "pay_method": "transfer",    // cash / wechat / bank_card / transfer
  "pay_date": "2026-05-12",
  "remark": "首付"
}
// → data: {
//     "recorded": true,
//     "funds_flow_id": 21,                 // 生成的付款流水
//     "offset_ids": [7],                   // 自动冲销记录
//     "paid_amount": 40000.00,
//     "flow_unapplied": 0.00,
//     "flow_unapplied_hint": "本次付款已全部用于冲销应付单…",
//     "arap": { "id": 12, "status": "closed", "settled_amount": 40000.00, "unsettled": 0.00 }
//   }

// 不填金额时：
// → data: { "recorded": false, "reason": "未填已付金额，应付单全额挂账", "arap": { ... } }
```

**规则**

| 情况 | 行为 |
|---|---|
| 不传 `paid_amount`（或 0） | 什么都不做；应付单保持全额挂账（`open`） |
| `paid_amount` > 该应付单未结额 | **400**，提示先到「往来」页核对（不静默少冲销） |
| 正常 | 生成一笔付款流水 + 冲销记录；应付单状态转 `partial` / `closed` |
| 成本**改金额**且该应付单**已有冲销** | **400**，提示先撤销冲销 |
| 成本**改金额**且无冲销 | 应付单金额同步更新，`status` 重算 |
| 成本**删除** | 应付单**保留**，删除接口返回 `payable.kept=true` 与提示文案 |

> 应付单的「自动生成」用 `cost_id IS NOT NULL` 识别；手工新增的应付单 `cost_id` 为空。
> 核心实现见 `backend/app/services/payable_service.py`。

## 9. 人工结算 `/api/labor`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/labor/preview` | 结算预览：按人汇总总工天、应发金额（**不写库、不新增成本**） |
| POST | `/api/labor/settle` | 保存结算单（按预览生成，重复生成时覆盖未发放部分） |
| GET | `/api/labor/settles` | 结算单列表（项目、状态） |
| POST | `/api/labor/settles/{id}/pay` | 登记发放（金额、日期、方式）→ 更新状态，**并生成付款流水 + 自动冲销该工人的应付单**（需求 T6） |
| DELETE | `/api/labor/settles/{id}` | 删除结算单（仅未发放的允许删除） |

```jsonc
// GET /api/labor/preview?project_id=1
// → { "items": [ { "worker_name": "张三", "total_days": 12.0, "amount_due": 3600.00 } ],
//     "total_amount": 3600.00, "note": "结算不重复计入成本" }

// POST /api/labor/settles/5/pay
{ "amount": 2000.00, "pay_date": "2026-07-05", "pay_method": "wechat" }
// → 除结算单字段外，额外返回（需求 T6）：
//   { "funds_flow_id": 21,                    // 本次发放生成的付款流水
//     "offset": { "applied": true, "offset_ids": [7, 8],
//                 "plan_total": 2000.00, "remaining": 0.00,
//                 "message": "按「同项目、同业务类型、日期最早优先」自动冲销 2 张单…" },
//     "offset_hint": "…" }
```

### 10.1 结算 ↔ 往来是同一本账（需求 T6 / T7）

- **发放即走账**：`/labor/settles/{id}/pay` 会生成付款流水（`biz_type=labor`、`partner=工人姓名`），
  并按第 6.1 节的自动冲销规则冲销该工人对应的应付单（同项目 → `labor` → 日期最早优先）。
  发放额超过该工人未结的应付单时，有多少冲多少，**超出部分留在流水上作为可冲余额**（不报错）。
- **人工费的付款入口只有结算页**（需求 T7）：往来页里 `biz_type=labor` 的应付单不再直接付款，
  界面按钮改为「去结算」跳转 `/labor-settle?project_id=&worker=`。
  该应付单**仍然显示**在往来页（保证"我欠谁的全面清单"总数对得上）。
- 其他业务类型（材料 / 机械 / 杂费 / 垫付）不受影响，仍在往来页付款。

## 13. 前端调用约定

- `api/client.ts`：axios 实例，`baseURL: '/api'`，`withCredentials: true`。
- 响应拦截：`code === 0` 直接返回 `data`；否则 `message` 用 `message.error()` 弹出，`401` 跳登录页，`403` 跳密保页。
- 所有金额字段在前端统一用 `MoneyInput` 组件（两位小数、千分位显示、提交时去掉千分位）。
- 日期筛选统一用 `DateRangeBar` 组件，传出 `start_date` / `end_date`。
- 列表分页统一 20 条，`Table` 的 `pagination` 与后端 `page/page_size` 对齐。
