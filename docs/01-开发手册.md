## 1. 技术选型

### 1.1 前端

| 用途 | 选型 | 说明 |
|---|---|---|
| 构建 | Vite 5 | 本地开发热更新快，打包产物由 FastAPI 托管 |
| 框架 | React 18 + TypeScript | 类型安全，组件复用 |
| 路由 | React Router 6 | 页面少，用一层扁平路由 |
| UI | Ant Design 5 | 表格、表单、日期区间、Modal 开箱即用，中文文档全 |
| 图表 | ECharts（echarts-for-react） | 第一版只用于成本构成饼图，可选 |
| 状态 | Zustand | 只存登录态、当前项目、字典缓存 |
| 请求 | axios | 统一拦截错误、统一 `{code,message,data}` |
| 日期 | dayjs | 日期区间筛选 |

### 1.2 后端

| 用途 | 选型 | 说明 |
|---|---|---|
| 框架 | FastAPI | 自带 OpenAPI 文档（`/docs`），便于自测 |
| ORM | SQLAlchemy 2.x | `Mapped[]` 声明式模型 |
| 校验 | Pydantic v2 | 出入参强校验 |
| 数据库 | SQLite（`backend/data/pims.db`） | 开启 `PRAGMA foreign_keys=ON`、`journal_mode=WAL` |
| Excel | openpyxl | 单文件多 Sheet，中文表头 |
| 密码 | `hashlib.pbkdf2_hmac`（标准库） | 不引入额外依赖，格式 `pbkdf2_sha256$迭代$盐$散列` |
| 会话 | HttpOnly Cookie + 服务端 token | 单用户，不需要 JWT 复杂度 |
| 运行 | uvicorn | `uvicorn app.main:app --port 8000` |

### 1.3 金额与日期规范（全项目统一）

- 金额：数据库 `NUMERIC(14,2)`，Python `Decimal`，前端展示 `toFixed(2)` + 千分位；**禁止 float 参与计算**。
- 业务日期：`DATE`（`YYYY-MM-DD`），由用户填写，**允许补录过去日期**，不允许晚于今天太多（见校验）。
- 时间戳：`created_at` / `updated_at` 为 `DATETIME`，系统自动写。
- 时间段筛选一律用**业务日期**（发生日期），不是创建时间。

## 2. 后端分层

```
backend/app/
├─ main.py            FastAPI 实例、CORS、静态托管、启动时建表与初始化
├─ config.py          配置：DB 路径、端口、Cookie 名、会话有效期（默认 7 天）
├─ db.py              engine、SessionLocal、get_db 依赖、PRAGMA 设置
├─ models/            SQLAlchemy 模型（一表一文件）
├─ schemas/           Pydantic 模型（XxxCreate / XxxUpdate / XxxOut）
├─ api/               路由层，只做参数校验与调用 service
│  ├─ auth.py  settings.py  projects.py  funds.py
│  ├─ costs.py  labor.py  ar_ap.py  inventory.py
│  ├─ dashboard.py  export.py
├─ services/          业务规则唯一实现处（路由层不得写业务判断）
│  ├─ auth_service.py        密码校验、密保、改密
│  ├─ project_service.py     项目档案与盈亏计算
│  ├─ cost_service.py        五类成本增删改 + 汇总
│  ├─ inventory_service.py   入库/领用/余量
│  ├─ offset_service.py      应收应付冲销
│  ├─ labor_service.py       工天汇总与结算
│  └─ export_service.py      多 Sheet Excel
└─ utils/             money.py、dates.py、changelog.py、errors.py
```

**分层铁律**

1. 路由层不写业务规则，只做「取参数 → 调 service → 返回 schema」。
2. 利润、库存余量、应收入账金额等**计算只在 service 层出现一次**，其他地方调用它。
3. 所有写操作必须经过 `utils/changelog.py` 记录变更。

## 4. 业务规则详述（实现口径）

### 4.1 利润计算（核心）

```
实际成本(project) = Σ 五类成本金额
                  = Σ(人工) + Σ(材料) + Σ(机械) + Σ(杂费) + Σ(垫付)     -- deleted = 0

预计利润 = 项目.甲方预算 − 项目.我方成本预算
结算利润 = 项目.甲方预算 − 实际成本
```

- **资金流水、应收、应付一律不参与上述任何一步。**
- 不做「现金结余」指标。
- 示例：甲方预算 400 万，我方成本预算 350 万 → 预计利润 400−350 = **50 万**；
  实际已花 160 万 → 结算利润 400−160 = **240 万**。

**成本预算使用进度**（辅助指标，不参与利润）：

```
预算使用率 = 实际成本 ÷ 我方成本预算 × 100%
预算余额   = 我方成本预算 − 实际成本
```

### 4.2 材料：采购即成本 + 按项目库存

录入「材料采购」时，**一个事务里做两件事**：

1. 写一条材料成本（`cost.type = 'material'`）；
2. 写一条库存流水（`inventory_txn.type = 'in'`，数量 +N，同时写 `cost_id` 便于追溯）。

录入「材料领用」时，**只写库存流水**（`type = 'out'`，数量 −N），**不写成本**。

```
库存余量(project, 材料名称, 单位) = Σ(in 数量) − Σ(out 数量)
```

- 领用校验：余量不足时**警告但允许继续**（工地常见先领后补录），页面标红提示。
- 不做退还、退货、项目间调拨；项目完工后剩余材料**不冲回成本**。

### 4.3 人工：实时入成本 + 结算不重复

| 环节 | 动作 | 是否动成本 |
|---|---|---|
| 每天录工天 | 写一条人工成本（金额 = 工日数 × 日工价，可手改金额） | ✅ 立即入成本 |
| 项目结束结算 | 按「项目 + 姓名」汇总总工天与应发金额，生成结算单 | ❌ 不重复入成本 |
| 发放工资 | 在结算单上记录发放金额/日期/方式，状态转「部分/已发」 | ❌ 不影响成本 |

- 不建工人档案，姓名手输；为减少错字，输入框做**历史姓名下拉建议**（来自本项目已录姓名）。
- 结算单可导出发放清单。

### 4.4 应收应付与手工冲销

```
应收单(type=receivable)：进度款 / 结算款      未收 = 金额 − 已冲销额
应付单(type=payable)   ：材料款/人工费/机械费/杂费/垫付/其他
```

- 录「收款」或「付款」时进入冲销界面：左侧列出该项目**未结清单据**，手工勾选并填本次冲销金额。
- 一个付款可冲多张单据（分次填金额）；一张单据可被多次冲销。
- 校验：单张冲销金额 ≤ 单据未冲销余额；本次冲销合计 ≤ 本次收付金额（允许少于，剩余作为预收/预付挂在流水上）。
- 单据状态：未收付 → 部分 → 已结清。
- **冲销不改成本、不改利润。**

### 4.5 修改与删除留痕

- 五类成本、流水、单据、库存流水均支持改 / 删。
- 每次写操作向 `change_log` 写一条：`table_name`、`record_id`、`action(create/update/delete)`、`before_json`、`after_json`、`operator`、`created_at`。
- 删除为软删除（`deleted = 1`），列表默认过滤，页面提供「显示已删除」开关。
- 修改记录在详情抽屉里以时间线展示，满足「留一条修改记录」。

### 4.6 校验规则

| 场景 | 规则 |
|---|---|
| 项目名称 | 必填，同名提示但允许 |
| 甲方预算 / 成本预算 | 必填、≥ 0；成本预算 > 甲方预算时黄字警告（不禁止） |
| 五类成本金额 | 必填、> 0；人工若填了工日数与日工价则自动算金额，允许手改 |
| 业务日期 | 必填；晚于今天时提示「未来日期，确认？」 |
| 材料单位 | 必填，取字典（吨/车/方/袋/米/根/件/个…），可自定义 |
| 机械计量 | 台班 / 小时 二选一，决定单位显示 |
| 杂费小类 | 必填，取字典（可现场新增） |
| 登录 | 密码错误 5 次锁定 1 分钟（轻量防猜） |

## 5. 页面设计

### 5.1 登录 / 初始化（`/login`）

1. 首次启动：只显示密码框，默认 `123456` → 登录后强制进入「设置密保」页（3 组问题+答案，必填，保存后才放行）。
2. 日常：密码框 → 进入首页。
3. 「忘记密码」：展示 3 个密保问题 → **全部答对** 才显示新密码设置框；任一错误则提示「密保答案不正确」，不透露是哪一题错。

### 5.2 首页：项目盈亏总表（`/`）

顶部：时间段筛选（默认今年）+ 导出按钮。主体表格（一屏看完所有项目）：

| 项目 | 状态 | 甲方预算 | 我方成本预算 | 预计利润 | 实际成本 | 结算利润 | 成本预算余额 | 已收 | 未收 | 已付 | 未付 |
|---|---|---|---|---|---|---|---|---|---|---|---|

- 预计利润、结算利润列加粗；结算利润为负标红。
- 点行进入项目详情。
- 底部合计行。

### 5.3 项目档案（`/projects`）

列表 + 新建/编辑抽屉。字段见 FR-2。删除项目需二次确认，提示「将同时隐藏该项目下的成本与流水」。
详情页（`/projects/:id`）用卡片分区：概览（两个利润 + 预算使用率进度条）、五类成本构成、资金往来、库存余量、人工结算。

### 5.4 记账：资金流水（`/ledger`）

列表按日期倒序：日期 / 项目 / 收付 / 类型 / 金额 / 对方 / 支付方式 / 备注 / 操作。
「新增收款」「新增付款」两个按钮；付款/收款保存后弹「是否立即冲销待结单据？」。

### 5.5 成本（`/costs`）

Tabs 五个页签，各自独立表格与「新增」表单：

| 页签 | 表格列 |
|---|---|
| 人工 | 日期 / 项目 / 姓名 / 工日数 / 日工价 / 金额 / 备注 |
| 材料 | 日期 / 项目 / 材料 / 数量 / 单位 / 单价 / 金额 / 供应商 / 备注 |
| 机械 | 日期 / 项目 / 设备 / 计量方式 / 数量 / 单价 / 金额 / 出租方 / 备注 |
| 杂费 | 日期 / 项目 / 小类 / 金额 / 备注 |
| 垫付 | 日期 / 项目 / 垫付人 / 金额 / 事由 / 备注 |

每个页签顶部显示该类别在筛选条件下的**合计金额**；行操作：编辑 / 删除 / 修改记录。

### 5.6 往来（`/arap`）

两个页签：应收单、应付单。列：日期 / 项目 / 类型 / 对方 / 金额 / 已冲销 / 未结 / 状态。
行内「收款/付款」按钮 → 冲销弹窗（勾选 + 填金额）。底部显示「该收未收合计」「该付未付合计」。

### 5.7 库存（`/inventory`）

先选项目（必选，体现隔离），两张表：
- 库存余量：材料 / 单位 / 入库合计 / 领用合计 / 余量
- 库存流水：日期 / 材料 / 类型（入库/领用）/ 数量 / 单价 / 供应商 / 关联成本 / 备注

### 5.8 人工结算（`/labor-settle`）

选项目 → 「生成结算预览」→ 按人汇总表格（姓名 / 总工天 / 应发金额 / 已发 / 未发 / 状态）→ 保存为结算单 → 行内登记发放。

### 5.9 设置（`/settings`）

杂费小类字典、材料与单位字典、修改密码（需 3 个密保全对）、导出全部数据、显示已删除记录开关。

### 5.10 Excel 导出

单个 `.xlsx`，Sheet 顺序与名称：

`项目盈亏` / `资金流水` / `人工` / `材料` / `机械` / `杂费` / `垫付` / `应收` / `应付` / `库存` / `人工结算`

- 表头中文加粗、冻结首行、列宽自适应、金额列千分位两位小数。
- 导出遵循当前页面筛选条件（项目、时间段）。

## 6. 开发路线（Roadmap）

| 阶段 | 任务 | 交付判定 |
|---|---|---|
| **P0 脚手架** | 前后端工程、SQLite 建表脚本、健康检查接口、前端路由与布局 | 访问 `localhost:8000/docs` 可见接口；前端能打开并跳转空页面 |
| **P1 登录与档案** | 密码登录、强制密保、改密；项目 CRUD、盈亏总表（空数据） | 能用默认密码登录、设密保、建 2 个项目并看到两个利润 |
| **P2 五类成本** | 五类成本 CRUD + 汇总 + 修改留痕 | 录 5 类成本后，项目实际成本 = 五类之和 |
| **P3 记账与往来** | 资金流水 CRUD；应收应付 + 手工冲销 | 能看到未收未付余额，冲销后状态流转正确 |
| **P4 库存与结算** | 材料入库/领用/余量（按项目隔离）；人工汇总结算 | 采购后余量增加、领用后减少；结算金额不重复入成本 |
| **P5 报表与导出** | 时间段筛选、项目详情、多 Sheet Excel 导出、示例数据 | 导出的 Excel 各 Sheet 数据与页面一致 |
| **P6 打包** | 一键启动脚本（`start.bat`）、静态托管、数据备份说明 | 双击即可用，无需命令行 |

## 8. 编码规范

- Python：`ruff` 风格，类型注解齐全；金额一律 `Decimal`；禁止在 SQL 里做金额四舍五入。
- TypeScript：`strict: true`，接口类型集中在 `src/types`，禁止 `any` 传参。
- 命名：数据库 `snake_case`，接口 JSON `snake_case`，前端组件 `PascalCase`，接口函数 `camelCase`。
- 提交粒度：一个功能点一次提交，提交信息写清「做了什么 + 对应 FR 编号」。
- 所有新增业务规则必须回写本文档第 4 节，保持文档与代码一致。
